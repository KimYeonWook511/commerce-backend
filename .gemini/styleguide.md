# Gemini Code Assist Style Guide

## 언어

- 리뷰 요약, 리뷰 코멘트, 수정 제안 설명은 한국어로 작성합니다.
- 코드 식별자, 파일 경로, 명령어, 패키지명은 원문 영어를 유지합니다.

## PR 리뷰 기준

- 기존 프로젝트 컨벤션과 문서화된 규칙을 우선합니다.
- Java, Spring Boot, Gradle, MySQL, JPA(Hibernate) 기반 백엔드 프로젝트임을 전제로 리뷰합니다.
- Controller는 요청 수신, 입력 검증, 서비스 위임, 응답 반환만 담당하는지 확인합니다.
- 비즈니스 로직은 Domain 또는 Service 계층에 있는지 확인합니다.
- 불필요한 추상화와 과한 설계를 권장하지 않습니다.
- 테스트 누락, 예외 처리 누락, 보안 위험, 동작 회귀 가능성을 우선적으로 지적합니다.

## PR 제목과 커밋 메시지

- PR 제목과 커밋 메시지는 `<type>: <subject>` 형식을 따릅니다.
- 허용 타입은 `feat`, `fix`, `refactor`, `test`, `docs`, `chore`입니다.
- `subject`는 한국어 현재형으로 작성하고 마침표로 끝내지 않습니다.
- `Update <file>`처럼 파일명만 설명하는 메시지는 사용하지 않습니다.
- 변경 의도가 드러나도록 작성합니다.

예:

- `feat: 상품 조회 API 추가`
- `fix: 인증 토큰 만료 처리 수정`
- `refactor: 결제 승인 서비스 책임 분리`
- `test: 인증 컨트롤러 예외 응답 테스트 추가`
- `docs: 상품 조회 API 문서 보강`
- `chore: PR 템플릿 리뷰 반영`

## 테스트

- 기본 테스트 명령은 `./gradlew test`입니다.
- 현재 `./gradlew test`는 `concurrency`, `test`, `batch` 태그 테스트를 제외합니다.
- 태그 제외 테스트가 변경 범위에 관련되면 별도 실행 필요성을 언급합니다.
