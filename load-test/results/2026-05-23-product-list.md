# 상품 목록 조회 baseline 측정 결과

## 측정 환경

- **k6 버전**: v2.0.0 (darwin/arm64)
- **측정 대상**: `GET /products` (로컬 백엔드)
- **백엔드 실행**: `./gradlew bootRun --args='--spring.profiles.active=local'`
- **DB**: MySQL 8.0 (Docker 로컬), 상품 101개
- **측정 일시**: 2026-05-23

## 설정

| 항목 | 값 |
|---|---|
| VUs | 50 |
| Duration | 1m |
| BASE_URL | http://localhost:8080 |
| p(95) threshold | < 200ms |
| 에러율 threshold | < 1% |

| 지표 | 값 |
|---|---|
| 총 요청 수 | 2,950 |

## Threshold 결과

| Threshold | 결과 |
|---|---|
| p(95) < 200ms | ✓ 통과 (45.67ms) |
| 에러율 < 1% | ✓ 통과 (0.00%) |

## 관찰 사항

- p95가 가설 SLO(200ms) 대비 **약 4.4배** 여유 있음. 로컬 환경 기준 응답시간은 충분히 안정적.
- 응답시간 분포가 p50(14ms)과 max(167ms) 사이에 넓게 분산. 가끔 느린 요청이 발생하나 outlier 수준.
- 에러 0건으로 안정성 확인.
- 인증 없는 단순 목록 조회 API로 DB 쿼리 부하가 낮음. 병목은 현 단계에서 식별되지 않음.
- 상품 101개 기준 결과이므로, 데이터 규모가 커질수록 응답시간 증가 가능성 있음. 인덱스 추가 및 페이징 적용 시 재측정 권장.

## 참고

- 시나리오: `load-test/scenarios/product-list.js`
- 이 결과는 로컬 머신 사양에 의존하므로 절대 수치보다 **개선 전후 상대 비교**에 활용한다.
- 가설 SLO(p95 < 200ms)는 첫 측정 전 설정한 값으로, 향후 시나리오에서 그대로 유지한다.
