# Claude Code 하네스 엔지니어링

## 목적

이 문서는 현재 Repo에서 Claude Code의 작업 방식을 일관되고 안전하게 운영하기 위한 하네스의 전체 방향을 정의한다.

하네스의 목적은 다음과 같다.

- 작업 흐름을 표준화한다.
- 위험한 작업을 통제 가능한 방식으로 다룬다.
- review와 검증 기준을 일관되게 유지한다.
- 작업 중 발생한 주요 결정, 방향 변경, 보류 사유를 추적 가능하게 만든다.
- 반복되는 작업 절차를 구조화하여 재사용 가능하게 만든다.

이 문서는 개별 skill, hook, script의 상세 사용법을 정의하는 문서가 아니라, 하네스 설계의 기준이 되는 상위 원칙을 설명한다.

## 핵심 원칙

- 먼저 탐색하고, 필요한 경우에만 질문한다.
- 작업은 가능한 한 작은 범위로 나누고, 변경 영향은 명확하게 다룬다.
- 구현은 항상 기존 아키텍처와 프로젝트 규칙을 우선한다.
- 위험한 작업은 명시적 승인이나 통제된 절차 없이 수행하지 않는다.
- 검증되지 않은 변경을 완료로 간주하지 않는다.
- 작업 중 중요한 결정과 방향 변경은 기록으로 남겨야 한다.
- 반복되는 절차는 일회성 지시로 남기지 않고 하네스 구조 안으로 편입한다.
- 결과는 자동 검증을 통과해야 완료로 인정한다.
- 검증은 가능하면 모델 진술보다 실제 실행 결과를 우선 근거로 삼는다.
- 작성과 검토는 가능한 한 분리된 역할로 다룬다.
- 역할별 규칙과 공통 컨텍스트는 분리해 관리한다.
- review는 실제 변경 내용과 실행 결과를 근거로 판단한다.

## Claude Code 실행 메커니즘

Codex와 달리 Claude Code는 다음 방식으로 하네스를 구현한다.

- **Plan Mode**: 구현 전 plan을 작성하고 `ExitPlanMode`로 사용자 승인을 받는다. Codex의 execute.py + Permission UI에 해당한다.
- **Hooks**: `.claude/settings.json`의 `hooks` 섹션에서 shell 명령으로 실행한다. Codex의 `.codex/hooks.json` + Python 스크립트에 해당한다.
- **Slash Commands**: `.claude/commands/*.md`에 정의된 명령으로 반복 workflow를 실행한다. Codex의 skill 진입점에 해당한다.
- **dev-start 실행기**: `.claude/skills/dev-start/scripts/execute.py`가 tmux pane을 생성하고 `claude -p`로 worker를 실행한다. Codex의 `execute.py + codex exec`에 해당한다.

## 기대 효과

이 하네스가 정착되면 다음을 기대할 수 있다.

- Claude Code의 작업 흐름이 예측 가능해진다.
- 위험한 명령이나 부주의한 Repo 조작 가능성이 줄어든다.
- review 품질과 검증 기준이 일정하게 유지된다.
- 작업 중 논의한 결정과 변경 이유를 나중에 다시 추적할 수 있다.
- 반복적으로 설명하던 절차를 구조화하여 운영 비용을 줄일 수 있다.
- 작업 방식이 사람의 기억에 의존하지 않고 시스템적인 규칙으로 축적된다.
