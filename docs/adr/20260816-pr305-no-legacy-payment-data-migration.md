# 기존 결제·예약 데이터를 이관하지 않고 파괴적 마이그레이션을 한다

- Status: accepted
- Date: 2026-08-16

## Context

결제 테이블 구조가 크게 바뀐다. 운영 데이터가 없다는 전제이며, 앞선 마이그레이션이 같은 전제로 이미 파괴적 변경을 한 선례가 있다.

## Decision

**기존 결제·예약 데이터를 폐기하고 새로 만든다.** 이관 규칙을 만들지 않는다.

이관을 한다면 예약 행과 결제 행을 짝지어 합치는 규칙, 짝이 없는 예약에 줄 상태, 활성 슬롯 유일 제약에 걸리는 옛 데이터의 처리, 환불 사건 키를 지어내는 방법을 정해야 한다. **그 결정들은 앞으로 다시 쓸 일이 없는 과거 형식만을 위한 것이다.**

결정적으로 **진행 중이던 환불 건은 이관해도 새 규칙을 적용할 수 없다.** 지금 코드가 호출마다 멱등키를 새로 만들고 저장하지 않아, 그 건이 무슨 키로 요청됐는지 알 길이 없다.

## Consequences

옛 결제·예약 데이터가 사라진다. 운영 데이터가 없다는 전제가 이 결정의 근거이므로, **운영 데이터가 있는 상태에서 이 결정을 근거로 삼아 같은 방식을 반복하면 안 된다.**

새 스키마가 이관 호환을 위한 절충 없이 설계된다.
