# 두 금액에서 나오는 파생값을 지금 코드로 만들지 않는다

- Status: accepted
- Date: 2026-09-01

## Context

결제 행의 환불 금액이 "돌려주기로 한 금액"과 "실제로 돌아간 금액" 둘로 갈리면 "아직 안 돌아온 금액"과 "결제사 잔액 추정"을 계산할 수 있게 된다. 그것이 이 분할의 동기이기도 하다. 그런데 지금 그 값을 읽는 곳이 없다 — 응답에 싣는 것과 결제사와 대조하는 것은 둘 다 범위 밖이다.

## Decision

파생값 접근자를 만들지 않는다. 값은 저장된 두 금액으로 언제든 계산된다.

## Consequences

- 사용처가 생길 때 그 자리에서 이름과 형태를 정한다. 지금 정하면 쓰는 쪽을 모른 채 이름을 짓게 된다.
- 이 작업이 만드는 것은 "그 값을 계산할 수 있는 상태"까지다.
