## ⚠️ 작성 규칙 (이 spec을 쓰는 agent가 반드시 지킬 것)

1. **추측 금지.** 대화에서 *명시되지 않은* 결정은 그럴듯하게 지어내 채우지 않는다.
   안 정해진 것은 둘 중 하나로 **드러낸다**:
   - 합리적 기본값이 있으면 → 그 값을 적되 `## 가정(Assumptions)`에 "이렇게 가정했다"고 명시한다.
   - 기본값이 없으면 → `[NEEDS CLARIFICATION: 구체적 질문]` 마커로 남긴다(Clarify 단계에서 해소).
2. **누락 금지.** 아래 필수 섹션은 비워 두지 않는다. 해당 없으면 "해당 없음"이라고 *적는다*.
   (조용히 빠지는 것을 막기 위함이다 — 빈 섹션이 곧 미검토 신호다.)
3. **테스트 가능하게.** 요구사항·완료 기준은 검증 가능한 형태로 적는다. 모호한 형용사
   ("빠르게", "안정적으로")는 수치/기준으로 바꾸거나 마커로 남긴다.
4. 각 요구사항·완료 기준에는 **ID**를 붙인다(`FR-001`, `SC-001` …). 이후 Analyze 단계가
   요구사항↔spec 커버리지를 이 ID로 추적한다.
5. **용어는 쉽게.** `CLAUDE.md`의 "문서 용어" 규칙을 따른다 — 표준 기술 용어는 그대로 쓰되,
   일반적이지 않은 비유·축약이나 난해한 표현은 쉽게 풀어써 명료하게 다듬는다.
