# Step 4 — partial-cancel-flow

## 목표

회원이 품목과 수량을 지정해 일부만 취소할 수 있게 한다. 요청 본문·접수 트랜잭션·재고 부분복구·응답 금액·실패 응답이 이 step에서 이어진다. 이 step이 끝나면 부분취소가 실제로 동작한다.

## 구현 지시

1. **시나리오를 테스트로 먼저 옮긴다.** 검증 대상이 적은 값과 경계를 그대로 쓴다 — 1만원 사과 3개와 2만원 배 1개, 사과 1개 취소 후 배 1개 취소, 사과 2개 취소가 접수된 뒤 같은 키로 배 1개(같은 금액 20,000).
2. **요청 본문을 받는다.** 품목 목록은 선택이며 없거나 비면 **잔여가 남은 품목의 잔여 전부**로 본다. 각 줄은 주문 품목 식별자와 1 이상의 수량이다. **같은 품목이 여러 줄이면 요청 경계에서 거부한다** — 도메인에도 두지 말고 한 곳에만 둔다.
3. **접수 트랜잭션을 흐름대로 잇는다.** 주문 행 잠금 → 결제 조회 → 기존 환불 조회(재생 판정, step 3에서 세운 것) → 상태 확인 → 승인 미확정 확인 → 주문의 검증·계산 → 환불 열고 저장 → 주문의 반영 → 재고 부분복구 → 저장.
4. **환불 금액은 주문이 계산한 값어치**를 넘긴다. 지금 결제에서 승인 금액을 꺼내 결제에 도로 넣는 자리를 그것으로 바꾼다. 결제의 금액 인자 시그니처는 그대로 둔다.
5. **재고 부분복구**는 취소한 품목만 골라 상품 식별자 오름차순으로 돌고, 복구 수량은 주문수량이 아니라 취소 요청 수량이다. 트랜잭션 맨 뒤 자리는 그대로 둔다.
6. **주문에 대조 관문을 하나 더 둔다.** 환불 식별자와 요청 줄 목록을 받아 같은지 다른지 답한다. 그 환불 식별자를 가진 내역을 모아 요청 줄과 품목 식별자로 짝짓고, **짝이 없거나 줄 수가 다르거나 수량이 다르면 다르다고 답한다.** 순서는 따지지 않는다.
   - **요청 줄이 비어 있으면 대조하지 않고 같다고 답한다.**
   - **저장된 내역이 하나도 없는데 요청 줄이 있으면 다르다고 답한다.** 이 작업 이전 환불에는 내역이 없어 무엇을 취소했는지 알 수 없고, 알 수 없는 것을 같다고 판정하지 않는다.
   - 이 관문이 step2가 아니라 여기 있는 이유: step2 시점에는 요청이 품목 목록을 받지 않아 대조할 것이 없다. 요청 본문이 생기는 이 step에서 함께 만들어야 관문과 그 입력이 같은 자리에서 검증된다.
   - 결제 쪽의 기존 금액·사유 대조는 걷어내지 않는다.
7. **응답의 두 금액이 뜻대로 나오게 한다.** 이번 환불액은 이번 요청으로 취소한 품목의 값어치이고, 남은 금액은 계약이 정한 정의를 유지한다. 필드를 새로 만들지 않는다.
8. **잔여수량 초과에 새 오류 코드 하나**를 더한다. 없는 품목 식별자와 같은 품목 중복은 기존 잘못된 요청으로 접는다. **결제 행 낙관 락 충돌에는 코드를 붙이지 않는다** — 번역 없이 전파해 공통 충돌 응답으로 나가게 둔다.
9. **결제완료 취소를 새 관문으로 옮기면서 기존 취소 메서드를 결제 전 전용으로 좁힌다.** 둘을 같은 자리에서 해야 한다 — 먼저 좁히면 아직 안 옮긴 결제완료 경로가 깨진다. 나머지 호출처 둘(사용자 직접 취소·배치 만료)은 결제 전만 다루므로 그대로 통과해야 한다.
10. 잘못된 승인을 되돌리는 보상 경로가 취소수량도 재고도 건드리지 않는 것을 확인한다. 그 경로를 고치지 않는다.

## 주의사항

- 하지 마라: 잔여수량이나 취소 값어치를 응용 계층에서 계산하는 것. 이유: 잔여수량이 저장되지 않는 파생값이라, 계산이 흐름으로 나가면 도메인이 자기 불변식을 잃고 다른 진입점이 생길 때 같은 계산이 복제된다.
- 하지 마라: 새 엔드포인트를 여는 것. 이유: 잔여 전부 취소도 부분취소의 특수한 경우이고, 주소를 나누면 잔여수량 검증·재고 복구·상태 전이·중복 방지가 두 벌이 된다.
- 하지 마라: 재생으로 걸린 요청에 결제사를 부르는 것. 이유: 한 사건에 두 주체가 겹쳐 상태 전이가 충돌한다.
- 하지 마라: 같은 품목 중복 거부를 요청 경계와 도메인 양쪽에 두는 것. 이유: 어느 쪽이 먼저 걸리느냐에 따라 응답이 갈린다.
- 하지 마라: 결제 행 낙관 락 충돌에 재시도를 붙이거나 주문 도메인 코드로 번역하는 것. 이유: 정상 경합이고 거절이 맞는 응답이다. 번역하면 같은 키가 처리 중인 것과 구분되지 않는다. 재시도 도입은 높은 경합이 실제로 관측될 때로 미룬 방침을 따른다.
- 하지 마라: 두 축(수량·금액)을 대조하는 장치를 만드는 것. 이유: 두 aggregate를 넘어 읽어야 해서 의존 방향을 깬다.
- 하지 마라: 결제 전 취소 경로와 보상 경로를 고치는 것. 이유: 범위 밖이며, 기존 검증이 그대로 통과해야 한다.
