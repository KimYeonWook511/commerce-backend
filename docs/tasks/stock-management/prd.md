# 기능 PRD

## 기능명

- `stock-management`

## 배경

- 기존 재고 도메인은 주문 생성과 취소 흐름에서 재고 차감/복구를 처리한다.
- 관리자 상품 관리 기능은 완료되었지만 상품별 초기 재고 생성, 운영 중 수동 재고 조정, 재고 변경 이력 관리는 아직 제공하지 않는다.
- 운영자가 재고를 직접 등록하고 변경 사유와 변경 주체를 추적할 수 있어야 주문 외 재고 변동을 관리할 수 있다.

## 목표

- 관리자가 상품별 초기 재고를 생성할 수 있게 한다.
- 관리자가 재고를 수동으로 증가 또는 감소할 수 있게 한다.
- 모든 관리자 재고 변경에 대해 변경 수량, 변경 사유, 변경 주체, 변경 시점을 이력으로 남긴다.
- 관리자가 상품별 재고 변경 이력을 조회할 수 있게 한다.

## 범위

- 포함 범위
- 관리자 초기 재고 생성 API
- 관리자 재고 증가 API
- 관리자 재고 감소 API
- 재고 변경 이력 저장
- 상품별 재고 변경 이력 조회 API
- 재고 변경 사유 enum 추가

- 제외 범위
- 주문 생성 재고 차감 로직 재설계
- 주문 취소 재고 복구 로직 재설계
- 재고 예약, 안전재고, 입출고 승인 workflow
- 재고 이력 pagination
- 관리자 UI

## 주요 시나리오

- 관리자가 상품 생성 후 해당 상품의 초기 재고를 등록한다.
- 관리자가 입고 또는 관리자 조정 사유로 재고를 증가시킨다.
- 관리자가 폐기 또는 관리자 조정 사유로 재고를 감소시킨다.
- 관리자가 특정 상품의 재고 변경 이력을 최신순으로 조회한다.

## 요구사항

- 관리자 재고 API는 `ROLE_ADMIN` 권한이 있어야 호출할 수 있어야 한다.
- 초기 재고 생성은 상품별로 한 번만 가능해야 한다.
- 초기 재고 생성 대상 상품은 삭제되지 않은 상품이어야 한다.
- `Product : Stock = 1:1` 관계를 유지해야 한다.
- 초기 재고 수량은 0 이상이어야 한다.
- 재고 증가/감소 수량은 0보다 커야 한다.
- 재고 감소는 현재 재고 수량보다 크게 요청할 수 없다.
- 관리자 재고 증가/감소는 비관적 락으로 재고 row를 조회한 뒤 처리해야 한다.
- 재고 변경 사유는 `INBOUND`, `DISPOSAL`, `ADMIN_ADJUSTMENT`, `ORDER_CANCEL_RESTORE` 중 하나여야 한다.
- 관리자 재고 변경 이력에는 변경 수량, 변경 사유, 관리자 member id, 변경 시점을 기록해야 한다.
- 증가 이력의 변경 수량은 양수로, 감소 이력의 변경 수량은 음수로 기록해야 한다.
- 이력 조회는 상품별 최신순 전체 목록을 반환한다.

## 제약사항

- Controller는 요청 검증, 권한 확인, 서비스 위임, 응답 반환만 담당한다.
- 재고 수량 변경과 이력 생성 정책은 Domain 또는 Service 계층에 둔다.
- 기존 공통 응답 포맷 `ApiResponse<T>`를 유지한다.
- 기존 공개 상품 조회 API의 재고 수량 응답 동작은 유지한다.
- 이번 phase에서는 실제 DB 마이그레이션 도구를 추가하지 않는다.
