# PRD — PAID 주문 취소·환불

## 배경

사용자 주도 주문 취소(`POST /orders/{orderId}/cancel`)는 현재 `INIT`(결제 전) 주문만
취소할 수 있다. `order.cancel()`이 INIT 외 상태를 거부하기 때문이다. 결제가 완료된
`PAID` 주문을 사용자가 취소하면 환불이 일어나야 하는데, 그 흐름이 비어 있다.

결제 환불 인프라(PG 취소 호출, CANCEL 결제 레코드 생성·상태 전이, UNKNOWN 대사)는
이미 보상(compensation) 경로에 존재하지만, "사용자가 정상 승인된 PAID 주문을 취소해
환불받는" 진입점이 없다.

## 목표

PAID 주문을 사용자가 취소하면 **전액 환불 + 재고 전체 복구**가 일어나도록 빈 흐름을 채운다.

## 범위

포함:
- `PAID` 주문 전체 취소 → 전액 PG 환불 + 재고 전체 복구.
- 환불 보장: 환불 의도를 주문 취소와 같은 tx에 영속화하고, PG 호출 실패·불확실·프로세스
  중단은 CANCEL 대사가 재시도하도록 위임한다.
- **CANCEL 대사 신설**: standalone CANCEL 결제(REQUESTED/UNKNOWN)를 스캔·구동하는 대사 경로를
  추가한다(기존 대사는 APPROVE만 스캔해 안전망이 비어 있었다). 이 신설이 위 환불 보장의 실제
  뒷받침이다.

제외:
- 부분취소(일부 상품·수량만 취소). OrderItem 단위 취소 추적·금액 안분 정책이 필요한 별도 작업.
- 포인트 복구. 포인트 도메인 미구현.
- `INIT` 사용자 취소·만료 배치(`ExpireOrderService`) 동작 변경. 기존 흐름 유지.

## 사용자 흐름

1. 사용자가 자신의 PAID 주문에 취소를 요청한다.
2. 시스템이 주문을 CANCELED로 전이하고, 재고를 복구하고, 환불 의도를 영속화한다(한 tx).
3. 커밋 후 PG 환불을 실행한다. 성공이면 환불 완료, 불확실(UNKNOWN)이면 대사가 마무리한다.
4. 사용자는 취소 접수 결과를 응답으로 받는다.

## 성공 기준

- PAID 주문 취소 시 주문이 CANCELED가 되고 재고가 전량 복구된다.
- 환불 의도가 주문 취소와 원자적으로 영속화되어, 어떤 시점에 프로세스가 중단돼도
  환불이 유실되지 않는다(대사가 마무리).
- 정상 승인된 결제(approve)의 SUCCEEDED 사실은 훼손되지 않는다(환불은 별도 CANCEL 레코드로 표현).
- 중복 취소 요청에도 환불이 한 번만 일어난다(멱등).
