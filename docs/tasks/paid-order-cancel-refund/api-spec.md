# API Spec — PAID 주문 취소·환불

기존 엔드포인트의 동작 범위를 확장한다. 새 엔드포인트는 없다.

## POST /orders/{orderId}/cancel

사용자가 자신의 주문을 취소한다. 인증된 회원 본인의 주문만 취소 가능하다.

### 변경점

- **이전**: `INIT` 주문만 취소(재고 복구). 그 외 상태는 거부.
- **이후**: `INIT`(기존: 재고만 복구)에 더해 `PAID` 주문 취소를 허용한다.
  PAID 취소 시 주문을 CANCELED로 전이하고, 재고를 전량 복구하고, 전액 환불을 진행한다.

### 요청

- Path: `orderId` (Long)
- 인증: 회원 토큰(본인 주문)

### 응답 (200 OK)

- 취소 접수 결과를 반환한다. 주문 식별자와 취소된 주문 상태를 포함한다.
- PAID 취소의 환불은 취소 접수 시점에 보장되며(영속된 환불 의도 + 대사), PG 환불 실행 결과는
  best-effort로 반영된다. 응답이 환불 진행 상태를 어떻게 노출할지(완료/처리중)의 구체 형식은
  step2 구현에서 확정한다.

### 실패

- 본인 주문이 아니거나 주문이 없으면 not found.
- 취소 불가 상태(예: 이미 CANCELED, 취소 허용되지 않는 상태)는 도메인 규칙에 따라 거부한다.
  구체 실패 코드·멱등 처리(중복 취소)는 step2에서 확정한다.
- PG 환불 실행 실패·불확실은 취소 접수를 무르지 않는다. 환불은 대사가 마무리한다.

> 실제 응답·실패 코드의 최종 형태는 step 구현 후 루트 `docs/api-spec.md`에 동기화한다.
