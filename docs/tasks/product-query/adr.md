# 기능 ADR

## 결정 제목

- 상품 조회 API를 공개 GET 엔드포인트로 추가하고 목록과 상세 응답을 분리한다.

## 배경

- 상품 조회는 MVP 기능이지만 아직 외부 API가 없다.
- 목록에서는 상품 탐색이 목적이고 상세에서는 구매 판단에 필요한 재고 수량이 필요하다.
- 재고를 목록까지 모두 포함하면 응답 책임이 커지고 불필요한 노출이 늘어난다.

## 결정 내용

- 상품 조회 API는 `GET /products`, `GET /products/{productId}` 두 개로 분리한다.
- 두 엔드포인트 모두 인증 없이 공개한다.
- 목록 조회는 `Product.createdAt DESC` 기준으로 최신순 정렬한다.
- 목록 응답은 `productId`, `name`, `price`만 반환한다.
- 상세 응답은 `productId`, `name`, `price`, `stockQuantity`를 반환한다.
- 상세 조회 시 재고 레코드가 없으면 예외가 아니라 `stockQuantity=0`으로 응답한다.

## 근거

- GET 공개 조회는 상품 탐색 진입 장벽을 낮춘다.
- 최신 등록순은 사용자가 최근 등록 상품을 먼저 확인하는 요구에 직접 대응한다.
- 목록과 상세 응답 분리는 필요한 정보만 노출하게 해 응답 구조를 단순하게 유지한다.
- 재고 누락을 `0`으로 표준화하면 데이터 정합성 이슈가 사용자 오류로 번지는 것을 줄일 수 있다.

## 결과

- `product` 패키지에 Controller, Service, 조회 결과 DTO가 추가된다.
- 목록 조회는 단순하고 가벼운 응답을 유지한다.
- 상세 조회는 stock 의존성을 가지지만 사용자에게 필요한 정보를 충분히 제공한다.
- 재고 레코드 누락을 운영 이슈로 숨기는 trade-off가 있으므로 테스트로 명시적으로 고정해야 한다.
