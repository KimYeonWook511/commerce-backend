# 기능 ADR

## 결정 제목

- 상품 관리는 관리자 API로 제공하고 삭제는 soft delete로 처리한다.

## 배경

- 상품은 주문 항목에서 참조되므로 물리 삭제하면 과거 주문 데이터 정합성이 깨질 수 있다.
- 상품 관리와 재고 관리는 운영 관심사가 다르고, 재고는 동시성 제어와 이력 요구사항이 별도로 존재한다.
- 파일 업로드까지 포함하면 외부 저장소와 업로드 정책 결정이 필요해 feature 범위가 커진다.

## 결정 내용

- 상품 삭제는 `deletedAt` 기반 soft delete로 처리한다.
- 상품 이미지는 파일 업로드 없이 `imageUrl` 문자열로 저장한다.
- 판매 상태는 `ProductStatus` enum으로 관리하며 `ON_SALE`, `SOLD_OUT`, `STOPPED`를 사용한다.
- 공개 조회는 `ON_SALE`, `SOLD_OUT`이고 삭제되지 않은 상품만 노출한다.
- 관리자 상품 API는 `@RequireRole(MemberRole.ROLE_ADMIN)`로 보호한다.
- 재고 수동 조정, 초기 재고 생성, 재고 이력은 이번 feature에서 제외한다.

## 근거

- soft delete는 주문 이력 보존 요구와 충돌하지 않는다.
- 상태 enum은 공개 조회 노출 정책과 운영 상태 변경을 명확하게 분리한다.
- `imageUrl` 저장은 현재 백엔드 범위 안에서 상품 표시 정보를 확장하는 가장 작은 변경이다.
- 재고 관리를 분리하면 동시성, 변경 사유, 이력 설계를 별도 feature에서 명확히 다룰 수 있다.

## 결과

- 상품 row는 삭제 후에도 유지되며 공개 조회에서는 제외된다.
- 품절 상품은 고객에게 계속 노출된다.
- 관리자 API가 추가되지만 별도 관리자 UI는 필요하지 않다.
- 재고 관련 운영 기능은 후속 feature가 필요하다.
