# 기능 PRD

## 기능명

- `product-management`

## 배경

- 현재 상품은 공개 조회와 주문 내부 참조에 사용되지만 관리자용 등록, 수정, 삭제 기능은 없다.
- `Product` 엔티티는 상품명과 가격만 가지고 있어 상품 설명, 이미지, 판매 상태, 삭제 상태를 표현할 수 없다.
- 운영자가 상품 판매 상태를 관리할 수 있어야 공개 상품 조회와 주문 가능 상품의 기준을 분리할 수 있다.

## 목표

- 관리자가 상품을 등록, 수정, soft delete 할 수 있게 한다.
- 상품에 설명, 이미지 URL, 판매 상태를 추가해 운영 관리에 필요한 최소 정보를 표현한다.
- 공개 상품 조회는 삭제되지 않았고 고객에게 보여도 되는 상품만 반환하도록 조정한다.

## 범위

- 포함 범위
- 관리자 상품 등록 API
- 관리자 상품 수정 API
- 관리자 상품 삭제 API
- 상품 설명, 이미지 URL, 판매 상태, soft delete 상태 추가
- 공개 상품 목록/상세 조회의 노출 조건 변경

- 제외 범위
- 재고 수동 조정
- 상품 생성 시 초기 재고 생성
- 재고 변경 이력
- 파일 업로드
- 카테고리, 검색, 필터, 페이지네이션
- 관리자 UI

## 주요 시나리오

- 관리자가 상품명, 가격, 설명, 이미지 URL, 판매 상태를 입력해 상품을 등록한다.
- 관리자가 기존 상품의 기본 정보와 판매 상태를 수정한다.
- 관리자가 상품을 삭제하면 실제 row는 보존되고 공개 조회에서 제외된다.
- 고객은 판매중 또는 품절 상태의 상품만 공개 목록/상세에서 조회한다.
- 고객은 판매중지 또는 삭제된 상품을 상세 조회할 때 상품 없음 오류를 받는다.

## 요구사항

- 관리자 상품 API는 `ROLE_ADMIN` 권한이 있어야 호출할 수 있어야 한다.
- 상품 등록 시 `name`, `price`, `status`는 필수다.
- `description`, `imageUrl`은 선택 값이다.
- `status`는 `ON_SALE`, `SOLD_OUT`, `STOPPED` 중 하나여야 한다.
- 상품 삭제는 hard delete가 아니라 soft delete로 처리해야 한다.
- soft delete 된 상품은 공개 목록과 상세 조회에서 제외되어야 한다.
- `STOPPED` 상품은 공개 목록과 상세 조회에서 제외되어야 한다.
- `ON_SALE`, `SOLD_OUT` 상품은 공개 목록과 상세 조회에 노출되어야 한다.
- 기존 주문과 주문 항목이 참조하는 상품 row는 삭제로 인해 사라지면 안 된다.

## 제약사항

- Controller는 요청 검증, 서비스 위임, 응답 반환만 담당한다.
- 상품 상태 변경과 삭제 정책은 Domain 또는 Service 계층에 둔다.
- 기존 공통 응답 포맷 `ApiResponse<T>`를 유지한다.
- 기존 공개 상품 조회 API의 경로는 변경하지 않는다.
- 파일 업로드는 구현하지 않고 `imageUrl` 문자열만 저장한다.
