# 기능 PRD

## 기능명

- `product-query`

## 배경

- 루트 PRD의 MVP 범위에는 상품 조회가 포함되어 있지만 현재 구현은 `Product` 엔티티와 저장소만 존재한다.
- 주문과 결제 흐름에서 상품 정보는 내부적으로 사용하고 있으나, 외부 사용자가 상품을 탐색할 공개 조회 API는 아직 없다.

## 목표

- 비로그인 사용자도 상품 목록과 상품 상세를 조회할 수 있게 한다.
- 상품 목록은 최신 등록 상품부터 노출해 최근 등록 상품 탐색성을 높인다.
- 상품 상세에서는 구매 판단에 필요한 현재 재고 수량을 함께 제공한다.

## 범위

- 포함 범위
- `GET /products` 공개 상품 목록 조회
- `GET /products/{productId}` 공개 상품 단건 조회
- 목록은 비페이지 전체 조회
- 상세 응답에 정확한 `stockQuantity` 포함

- 제외 범위
- 상품 등록, 수정, 삭제
- 검색, 카테고리, 필터, 페이지네이션
- 목록 응답의 재고 정보 노출

## 주요 시나리오

- 비로그인 사용자가 최신 등록순으로 전체 상품 목록을 조회한다.
- 비로그인 사용자가 특정 상품의 이름, 가격, 재고 수량을 확인한다.
- 존재하지 않는 상품 ID로 상세 조회 시 오류 응답을 받는다.

## 요구사항

- 상품 목록 조회 API는 인증 없이 호출 가능해야 한다.
- 상품 목록은 `createdAt DESC` 기준으로 최신순 정렬되어야 한다.
- 목록 응답은 `productId`, `name`, `price`만 포함해야 한다.
- 상품 상세 조회 API는 인증 없이 호출 가능해야 한다.
- 상세 응답은 `productId`, `name`, `price`, `stockQuantity`를 포함해야 한다.
- 상품은 존재하지만 재고 레코드가 없으면 `stockQuantity`는 `0`으로 응답해야 한다.
- 존재하지 않는 상품 상세 조회는 기존 product 예외 체계를 사용해 `404`로 응답해야 한다.

## 제약사항

- 기존 계층 구조 `Controller -> Service -> Domain/Repository`를 유지해야 한다.
- Controller는 요청 수신과 응답 반환만 담당하고 비즈니스 로직은 Service에 둔다.
- 기존 공통 응답 포맷 `ApiResponse<T>`를 유지해야 한다.
- 테스트는 컨트롤러와 서비스 레이어에 추가해야 한다.
