# 에이전트 가이드

이 문서는 현재 Repo에서 사용할 수 있는 Codex 에이전트를 설명하는 안내 문서입니다.

에이전트의 실제 정의 파일은 `.codex/agents/*.toml`에 있으며, 각 파일에는 에이전트 이름, 설명, 모델, 권한, 세부 동작 지침이 들어 있습니다.

## 사용 가능한 에이전트

### `spring-boot-engineer`

- 용도: Spring Boot 서비스 동작, 설정, API 구현, JPA 동작을 다룰 때 사용합니다.
- 강점: 컨트롤러-서비스-리포지토리 경계, 트랜잭션, 검증, 보안 필터, DTO 계약을 기준으로 작은 범위의 안전한 수정에 강합니다.
- 권한: `workspace-write`
- 추천 상황:
  - API 엔드포인트를 추가하거나 수정할 때
  - 서비스 계층 로직을 구현하거나 수정할 때
  - JPA 조회 흐름이나 검증 응답을 다듬을 때

### `test-writer`

- 용도: 자동화 테스트 작성, 회귀 테스트 보강, 테스트 구조 개선에 사용합니다.
- 강점: 결정적이고 유지보수 가능한 테스트를 빠르게 추가하고, 실패 경로와 회귀 위험을 커버하는 데 강합니다.
- 권한: `workspace-write`
- 추천 상황:
  - 신규 기능에 대한 테스트가 필요할 때
  - 버그 재발 방지 테스트를 추가할 때
  - 서비스나 컨트롤러 테스트 범위를 보강할 때

### `java-architect`

- 용도: Java 애플리케이션 구조, 모듈 경계, 예외 전파, JVM 관점 검토가 필요할 때 사용합니다.
- 강점: 큰 구조를 무리하게 바꾸지 않고, 기존 아키텍처를 유지하면서 가장 작은 안전한 수정 방향을 잡는 데 강합니다.
- 권한: `workspace-write`
- 추천 상황:
  - 서비스 경계가 흐려져 구조 정리가 필요할 때
  - 예외 흐름이나 계약 안정성을 점검할 때
  - 특정 변경이 아키텍처적으로 안전한지 검토할 때

### `database-optimizer`

- 용도: 데이터베이스 성능, 인덱스, 쿼리 플랜, 락 경합, 스키마 구조 검토에 사용합니다.
- 강점: 실제 접근 패턴과 워크로드를 기준으로 병목을 분석하고, 가장 작은 고효율 개선안을 제시합니다.
- 권한: `read-only`
- 추천 상황:
  - 특정 조회나 쓰기 작업이 느릴 때
  - 인덱스 추가 또는 스키마 조정이 필요한지 판단할 때
  - ORM 생성 쿼리나 조인 전략이 비효율적일 때

### `pr-reviewer`

- 용도: PR 리뷰 관점에서 정확성, 회귀, 보안, 테스트 누락을 점검할 때 사용합니다.
- 강점: 스타일보다 실제 장애 가능성과 사용자 영향, 테스트 공백을 우선으로 봅니다.
- 권한: `read-only`
- 추천 상황:
  - 머지 전 변경 위험을 검토할 때
  - 회귀 가능성이 높은 수정 사항을 점검할 때
  - 변경 범위 대비 테스트가 충분한지 확인할 때

### `security-reviewer`

- 용도: 인증/인가, 입력 검증, 시크릿 처리, 설정 보안 검토에 사용합니다.
- 강점: 공격 경로, 영향도, 악용 전제조건을 분리해서 보안 위험을 평가합니다.
- 권한: `read-only`
- 추천 상황:
  - 로그인, 권한, 토큰 처리 로직을 검토할 때
  - 외부 입력 경로의 검증과 주입 가능성을 확인할 때
  - 비밀 정보나 설정 노출 위험을 점검할 때
